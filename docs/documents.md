# OpenSI document workspace

Open **Hujjatlar** in the navigation, **Panellar → Hujjatlar**, or a project's **Hujjatlar** result tab.

- **Hujjat yaratish** opens the document category in Creative Studio. Choose a connected text model and supply the content, language and requirements. Document, presentation and spreadsheet presets produce editable Office files and attempt a PDF export automatically.
- **Fayl yuklash** stores existing files in the private library. Unknown formats remain downloadable without pretending to support conversion.
- **Ko‘rish** renders PDF pages locally in the dashboard. For supported Office/text/image sources it first creates a separate PDF. Page navigation works on desktop and mobile.
- **Aylantirish** creates a new export; it never overwrites the source. The conversion history records success or an actionable error. Closing/reloading the tab does not cancel a server job.
- **Yuklab olish** downloads the original or generated bytes through an authenticated owner-only endpoint.

## Supported conversions

| Input | Output |
|---|---|
| DOC, DOCX, ODT, RTF, TXT, Markdown, HTML | PDF, DOCX, ODT, RTF, TXT |
| XLS, XLSX, ODS, CSV, TSV | PDF, XLSX, ODS, CSV |
| PPT, PPTX, ODP | PDF, PPTX, ODP |
| PNG, JPEG, WebP | PDF |
| PDF | Preview and original download |

The original extension is omitted from conversion choices. PDF-to-editable-Office conversion and OCR are not included. CSV and TXT inherently lose formatting; CSV exports a single sheet. Complex Office layouts, uncommon fonts and interactive HTML may render differently. HTML printing disables JavaScript and external network resources; include local images/styles in the project.

Uploads/downloads remain bounded at 1 GB per file. Conversion and PDF preview are limited to 50 MB per file. Conversion runs for at most 110 seconds with two server workers and one worker per project. Large, damaged or password-protected inputs may fail with a visible error. Output storage checks reserve free server space and honor the 2 GB project boundary. A server restart marks interrupted conversions failed rather than reporting false success.

## Model integration

API agents with file-write tools in cloud projects receive `document_convert`. Native CLI models can write `opensi-export.json` containing the current run ID and at most five source/format requests; the server validates and executes these after source synchronization. Stale manifests from previous turns are ignored. The same conversion engine is used by Creative Studio and the dashboard.

## Runtime

Build `docker build -f deploy/runner/Documents.Dockerfile -t opensi-documents:0.1.0 .` after the existing `opensi-runtime:0.3.0` image is available. Verify both image tags before restarting the runner; a missing tag causes terminal and PDF jobs to exit with Docker code 125. The private runner selects the document image only for a validated document command. Office conversion uses LibreOffice; HTML/Markdown/image PDF printing uses Chromium. The job has no network or credentials, a read-only root, dropped capabilities, fixed CPU/memory/process/file limits and one owned workspace mount. Office macros are disabled by the high-security profile.

Before declaring a VPS deployment ready, request `/api/ready`; it returns HTTP 200 only when the private runner can see both the runtime and PDF image. `/api/health` only checks that the web process responds. A live HTML-to-PDF conversion should still be tested after deployment because an image tag alone does not prove that Chromium/LibreOffice can render a file.

Tests are in `tests/documents.test.mjs`; they cover format validation, private ownership, path traversal, original preservation, persisted jobs, runtime failures, source import, isolated command selection, current-run manifests and PDF signature verification.
