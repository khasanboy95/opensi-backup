# Creative runtime and model teamwork

Runtime image `opensi-runtime:0.14.0` provides Blender in headless CPU mode, FFmpeg/ffprobe, Python scientific/media/document libraries, and Three.js/React Three Fiber/Drei/cannon-es/Phaser/GSAP alongside the existing compilers and browser. `runtime_info` reports actual installed versions; `/opt/toolchain/python-installed.txt` records the built Python dependency versions. This is a curated toolchain, not every library on PyPI/npm.

Use `run_command` to execute project scripts. Blender: `blender -b -t 1 --python scene.py`; create `.blend`, PNG and GLB outputs. Use CPU Cycles on this VPS with bpy.context.scene.cycles.use_denoising=False: the Debian build lacks OpenImageDenoiser. Use --python-exit-code 1 to propagate script failures. FFmpeg: use `-threads 1`, bounded duration/resolution, and verify with ffprobe. Python MoviePy uses the v2 API. Pygame uses dummy video/audio drivers for headless tests; GUI windows do not become browser previews. For interactive games use a bundled Three.js/Phaser web build. Save an index.html linking generated artifacts for browser preview/download.

Generated files can be up to 1 GB per file, with core dumps disabled. Each command still has the 110-second/768-MB sandbox budget; there is no GPU. Split larger renders into frame batches. Ordinary shell jobs remain offline. Additional Python wheel packages use the dedicated installer described below; other base software is installed when building the runtime. Webhooks retain bounded public HTTPS through the broker. Browser observation/navigation/click/fill/press/category exploration remain available through computer tools and preserve their approval/ownership checks.

`youtube_analyze` accepts a public YouTube video URL, retrieves available metadata and caption text, and writes evidence to `inputs/youtube-<id>.json`. It does not bypass login restrictions, download protected video or claim to have watched frames. Missing captions are explicit; users can upload source media or subtitles for FFmpeg/Python processing.

Automatic complex tasks start two distinct enabled API model consultations concurrently (prefer different providers), sharing task intent and project inventory. Their advice is merged into the main agent context. File modifications remain coordinated by the main execution loop; specialist `consult_model` calls may perform further work sequentially, including supported native CLI models. The final review prefers a different available model and retains that reviewer across its repair steps. Hosted Antigravity pending shell requests also use this cloud runtime; small text sources are synchronized back to its CLI and binary artifacts stay in the cloud dashboard. Personal local connectors retain their own installed software. Usage is recorded for consultations; a failed advisory provider does not discard the project. No benchmark claim is made from model names; routing preferences are heuristics.

References: [Blender CLI](https://docs.blender.org/manual/en/latest/advanced/command_line/render.html), [FFmpeg](https://ffmpeg.org/ffmpeg.html).

Runtime 0.14 adds `install_packages` for missing Python distributions. The agent selects actual PyPI names (optional exact versions), installs wheel dependencies into `.opensi-python`, and verifies the import/task again. A per-job authenticated CONNECT proxy only permits PyPI registry and wheel hosts; ordinary jobs remain offline. Downloads are bounded to 300 MB, installer time to 95 seconds, and installation pauses below 1 GB free disk. Source builds, arbitrary URLs and OS/GPU driver installation are not covered. `python-packages.lock.json` records installed versions. Project packages stay private and do not enter ZIP exports. Local connector ZIP includes project PYTHONPATH support; older connectors can set it in their own command. Hosted Antigravity simple `python -m pip install NAME` requests use the same cloud installer.

`youtube_analyze` tries JSON3, XML and VTT captions. When no caption is supplied, it returns actionable alternatives rather than fabricated video content. `transcribe_media` extracts up to 120 seconds from an uploaded project video/audio file, calls the configured ASR provider, and saves MP3/TXT evidence. Long media requires successive offsets. It cannot obtain inaccessible YouTube source media merely by installing a library. ASR accuracy and language coverage depend on the actual provider.

The environment picker separates execution from delivery: cloud, an online paired computer with its workspace path, and cloud results saved to a chosen browser folder or ZIP. A personal connector's disk/root is selected using Start-Windows.cmd (or --workspace). Mobile browsers can control cloud/paired-computer execution and download files, but do not expose a local Python/Blender OS terminal. Direct folder access is offered only when supported; fallback is ZIP. Folder delivery requires the browser to remain open and permission to write; blocked automatic downloads can be repeated using Save result.
